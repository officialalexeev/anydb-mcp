# Полное руководство по публикации проекта (GitHub + NPM)

Этот документ описывает процесс профессиональной публикации пакета `anydb-mcp`. Следуйте этим шагам, чтобы ваш проект стал доступен всему миру как Open Source решение высокого уровня.

---

## Часть 1: Финальная проверка (Pre-flight Check)

Перед публикацией убедитесь, что код стабилен.

1.  **Запуск тестов:**
    ```bash
    npm test
    ```
    *Все тесты должны пройти (зеленый цвет).*

2.  **Проверка сборки:**
    Проверьте, что в `package.json` указана правильная версия (например, `1.0.0`) и имя пакета (`anydb-mcp`).

3.  **Проверка игнорируемых файлов:**
    *   `.gitignore`: Должен исключать `node_modules`, `.env`, `coverage`.
    *   `.npmignore` (или поле `files` в `package.json`): Гарантирует, что в npm не попадут тесты и конфиги CI. Мы настроили `files: ["src/", "docs/", "README.md", "CHANGELOG.md", "LICENSE"]`, так что это делается автоматически.

---

## Часть 2: Публикация на GitHub

Если вы публикуете проект впервые:

1.  **Инициализация Git:**
    ```bash
    git init
    git branch -M main
    ```

2.  **Добавление файлов:**
    ```bash
    git add .
    git commit -m "Initial release v1.0.0: AnyDB MCP Server"
    ```

3.  **Создание репозитория:**
    *   Зайдите на [GitHub.com](https://github.com/new).
    *   Создайте новый **публичный** репозиторий с именем `anydb-mcp`.
    *   **Важно:** Не добавляйте README или License при создании (они у нас уже есть).

4.  **Связывание и отправка:**
    ```bash
    # Замените your-username на ваш ник
    git remote add origin https://github.com/your-username/anydb-mcp.git
    git push -u origin main
    ```

---

## Часть 3: Публикация в NPM

1.  **Вход в аккаунт:**
    ```bash
    npm login
    ```
    *Вас попросят нажать Enter, откроется браузер для авторизации. После успешного входа вернитесь в терминал.*

2.  **Проверка имени:**
    Убедитесь, что имя `anydb-mcp` свободно на [npmjs.com](https://www.npmjs.com/). Если занято: измените `name` в `package.json` (например, на `@ваш-ник/anydb-mcp`).

3.  **Публикация:**
    ```bash
    npm publish --access public
    ```
    *Флаг `--access public` обязателен, если вы используете scoped-имя (с @).*

**Поздравляем! Ваш пакет доступен всему миру по команде `npx anydb-mcp`.**

---

## Часть 4: Выпуск обновлений (Release Cycle)

Когда вы внесли изменения и хотите обновить пакет:

1.  **Закоммитьте изменения:**
    ```bash
    git add .
    git commit -m "Fix: исправление бага с парсингом Redis"
    ```

2.  **Обновите версию:**
    Используйте команду npm для автоматического обновления версии в `package.json` и создания Git-тега.
    
    *   Для исправления багов (1.0.0 -> 1.0.1):
        ```bash
        npm version patch
        ```
    *   Для новых функций (1.0.0 -> 1.1.0):
        ```bash
        npm version minor
        ```
    *   Для ломающих изменений (1.0.0 -> 2.0.0):
        ```bash
        npm version major
        ```

3.  **Опубликуйте:**
    ```bash
    git push origin main --tags  # Отправка кода и тегов на GitHub
    npm publish                  # Публикация новой версии в NPM
    ```

---

## Часть 5: Автоматизация (CI/CD)

В проекте уже настроен файл `.github/workflows/ci.yml`.
После того как вы сделаете `git push`, зайдите во вкладку **Actions** в вашем репозитории на GitHub. Вы увидите, как GitHub автоматически запускает ваши тесты на разных версиях Node.js.

Это добавляет проекту профессиональный статус "Passing", который привлекает пользователей.
